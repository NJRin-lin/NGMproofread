# macOS ChatGPT 账号接入（待用户验收）

分支：`feature/chatgpt-connection`。基于 `b6b4377`，不合并 main；Windows 暂未改动。

## 范围

保留图片识别和文字输入布局。在设置中区分现有 OpenAI API 与新增 ChatGPT 账号登录：

- ChatGPT 账号：使用官方 Sign in with ChatGPT OSS 动态注册、系统浏览器登录及计划额度授权。
- OpenAI API：保留原有 API Key 调用，独立于 ChatGPT 账号。
- 免费网页版：提供明确标注的网页入口，需要用户手动提交文字；不宣称免费账号具备自动调用权限。

不读取 Codex 凭据、浏览器 Cookie 或 ChatGPT 私有接口。ChatGPT 登录信息保存在 macOS 钥匙串；普通偏好只保存主机标识和账号选择。

## 实现

- `127.0.0.1` 临时端口回调；随机 state、nonce、PKCE S256；校验回调状态和已注册 client ID。
- 验证 ID token 的 RS256 签名、issuer、audience、有效期和 nonce，然后激活账号；保存每个 client ID 对应的账号。
- 支持多账号选择、重新授权、刷新令牌和退出。退出尝试撤销远程会话；失败时明确提示用户在 ChatGPT 设置中断开。
- 从账号模型目录读取可见模型，保存选择。Responses 请求使用 `store:false`、`stream:true`，不发送此通道不支持的参数。
- 只把收到 `response.completed` 的非空文本作为成功；拒绝额度错误、失败、截断或中断的回复。
- 翻译、句子分析及词汇查询通过现有 AIService 分发。切换服务清理分析缓存，翻译结果标明来源，增加重新翻译入口。
- AI 错误单独提示，避免被已有 OCR 或文字输入界面遮挡。

## 测试

离线测试：`sh Tests/run-chatgpt-tests.sh`。覆盖 PKCE、回调校验、授权检查、请求参数、SSE 完成与失败、JWT 签名及身份声明。

构建：

```sh
xcodebuild -project OCR-Translate.xcodeproj -scheme OCR-Translate -configuration Release -derivedDataPath build/chatgpt-release CODE_SIGNING_ALLOWED=NO build
codesign --force --deep --sign - build/chatgpt-release/Build/Products/Release/OCR-Translate.app
```

离线测试在受限沙盒内生成临时 RSA 密钥时被系统拒绝；经授权在沙盒外执行，14 项通过。测试使用临时密钥与虚构账号，不访问用户账号或网络。

自动界面验收未完成：电脑操作权限未授予。真实登录和模型推理尚未验证，不能以编译通过代替端到端验收。

## 用户验收步骤

1. 运行测试版，打开设置 → ChatGPT 账号（使用计划额度）。
2. 点击 Continue with ChatGPT，在浏览器中完成登录并决定是否授权 NGM proofread 使用计划额度。
3. 返回 NGM，确认账号和可用模型显示；没有权限时应明确提示，不应显示为可用。
4. 用简短日文测试翻译、句子分析、词汇查询；检查结果来源显示 ChatGPT。
5. 关闭并重开应用，确认连接保留；切换回 DeepSeek，确认原功能仍可用。
6. 测试取消登录、添加其他账号、切换模型、重新翻译和退出；退出后不得继续自动调用该账号。
7. 如果账号不支持计划授权，可使用网页入口作人工参考；该入口没有自动回填功能。

等用户测试并明确确认后，才考虑合并 main。
